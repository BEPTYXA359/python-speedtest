# speedtest.py — замер скорости скачивания

Консольный скрипт на чистом Python: делает N последовательных HTTP-запросов
к заданному адресу, дожидается полного ответа на каждый и печатает время
каждого запроса, суммарный объём скачанных данных и среднюю скорость.
Только стандартная библиотека, зависимостей нет.

**Требования:** Python 3.8+ (macOS / Linux / Windows).

## Запуск

```bash
# дефолт: Cloudflare, 10 запросов по 25 МБ
python3 speedtest.py

# свой адрес: тяжёлый файл (~16 МБ) с зеркала Яндекса, 3 запроса
python3 speedtest.py -n 3 https://mirror.yandex.ru/debian/ls-lR.gz

# справка по всем флагам
python3 speedtest.py --help
```

Дефолтный адрес — `https://speed.cloudflare.com/__down?bytes=25000000`:
эндпоинт Cloudflare, отдающий ровно запрошенное число байт. У статических
файлов (как на зеркале выше) размер задаёт сам файл: флаг `--size` лишь
подставляет query-параметр `bytes` в URL, и такие серверы его игнорируют.

## Флаги

| Флаг | По умолчанию | Описание |
|---|---|---|
| `url` (позиционный) | Cloudflare, 25 МБ | Адрес для замера, только `http`/`https` |
| `-n`, `--requests N` | 10 | Число последовательных запросов, ≥ 1 |
| `--timeout СЕК` | 30 | Таймаут сетевых операций одного запроса |
| `--size МБ` | 25 | Размер скачивания: подменяет параметр `bytes` на `N × 10⁶` |
| `--unit {mbs,mbps,kbs}` | `mbs` | Единица скорости в итоге: МБ/с, Мбит/с или КБ/с |
| `--no-progress` | выключен | Не рисовать прогрессбар (при пайпе его и так нет) |
| `-h`, `--help` | — | Справка |

Ошибки: неверные аргументы — код 2, сетевые проблемы и HTTP-ошибки — код 1
с сообщением в stderr, Ctrl+C — код 130.

## Единицы

Все единицы десятичные (SI), как принято в замерах скорости:

- 1 КБ = 10³ байт, 1 МБ = 10⁶ байт;
- 1 Мбит = 10⁶ бит, 1 байт = 8 бит → **1 МБ/с = 8 Мбит/с**.

Дефолт — МБ/с: скрипт меряет скачивание файлов, и мегабайты в секунду прямо
отвечают на вопрос «насколько быстро льются данные». Мбит/с — единица, в
которой провайдеры продают тарифы, — всегда печатается рядом в скобках;
`--unit mbps` просто меняет их местами (тогда в скобках будут МБ/с).

## Как это работает

- **Чтение блоками.** Тело ответа читается кусками по 64 КиБ и сразу
  отбрасывается — файл не задерживается в памяти, объём считается суммой
  длин блоков.
- **Без сжатия.** Запрос идёт с `Accept-Encoding: identity`, поэтому сервер
  не сжимает ответ, и счётчик байт равен объёму, реально прошедшему по сети.
- **Что входит во время запроса.** Замер (`time.perf_counter()`) охватывает
  соединение (TCP/TLS), отправку запроса, ожидание и чтение всего тела,
  включая автоматические редиректы и их DNS. DNS основного адреса
  выполняется до старта замера — при проверке URL.
- **Прогрессбар не искажает замер.** Бар пишется в stderr (не смешивается
  с выводом результатов в stdout) и перерисовывается не чаще ~10 раз/с —
  троттлинг по времени, так что накладные расходы отрисовки ничтожны.
  Если stderr — не терминал (пайп, CI), бар не рисуется вовсе;
  `--no-progress` отключает его принудительно.
- **User-Agent** — `speedtest.py/1.0`: некоторые CDN отклоняют запросы
  с дефолтного агента питона (тем самым `Python-urllib/...`).
- **Ограничение чужих серверов.** Некоторые хосты режут загрузку больших
  файлов по HTTP/1.1 кодом 429 (например, `upload.wikimedia.org`) — это
  политика сервера, а не ошибка скрипта.
